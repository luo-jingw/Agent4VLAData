## 1 总体架构（组件视图）

```
规则层（配置+判据，版本化）
  data_schema.yaml / criteria.yaml / constraints.yaml
    ↓ 读
决策层（agent：调节/搜索/分析）——第一阶段只提议不删除
    ↓ function call
执行层
  管线脚本（十模块）+ 离线指标工具（与 agent 解耦，只暴露接口）
    ↓ 产出
状态工件
  标注列（parquet）+ 结果矩阵（CSV）+ provenance（判据+配置+理由）
    ↓ 驱动
验证层
  下游训练对比（终审）+ 人审边缘案例
```

## 2 十模块的接口与文件

### ① 数据定义与接入

- 输入：原始录制（LeRobot v2.1 源目录，30 fps，state 28 / action 24，三路相机）。
- 输出：数据字段说明 + 格式版本（进 provenance）。
- 接口：`data_schema.yaml`（字段语义/单位/坐标系/有效性规则）。
- 文件：新增 `config/data_schema.yaml`；读源数据逻辑吸收 reference 包惯例。
- TBD：字段清单逐维核对（关节 22 + 吸盘二值 + 真空反馈的语义文档化）。

### ② 完整性检查与时间对齐

- 输入：原始录制 + schema。
- 输出：有效性标记（每帧/每流）+ 对齐误差报告。
- 接口：`check_integrity(src) -> {validity_mask, report}`。
- 判据：缺帧/重复帧/时钟偏移；**事件窗对齐检查**（命令沿与反馈读数、
  图像帧的对应关系，判据阈值 TBD）。
- 文件：新增 `check_integrity.py`（可吸收 verify_dataset.py 的行数/帧数一致性
  检查逻辑）。
- TBD：多相机时间戳语义（曝光/接收）的实测方法（GAP-10，无文献可抄）。

### ③ 分层标注与质量诊断

- 输入：对齐数据 + 规则层判据。
- 输出：标注列——episode 级（任务/异常/冗余）+ 帧级（事件/次优/可分性），
  每条附理由；可分性标注在 ⑤ 之后计算（框架约束）。
- 接口：
  - 几何部分（确定性）：停顿/无效游走/有效位移三分（吸收 eef_geometry.py）；
  - 语义部分（agent）：事件定义、次优帧判据、冗余 action 点、可分性判据
    ——输出结构化判断对象（见框架 §5.2）。
- 文件：新增 `annotate/`（几何标注脚本）；语义标注由 agent 产出、落 parquet
  新列（如 `frame_event`、`frame_suboptimal`、`frame_observability`）。
- TBD：标注列 schema 的精确字段与枚举值。

### ④ 清洗与样本选择

- 输入：标注 + 清洗规则配置（A 类旋钮的阈值）。
- 输出：样本清单（保留/隔离/裁剪）+ 处理记录（含候选与原因）。
- 原则：**候选+解释**——规则产出候选列表（p95 时长、切换次数、方差尖刺），
  agent/人解释后才执行删除；删除需验证条件满足（框架约束层）。
- 接口：`clean(dataset, annotations, rules) -> {sample_list, candidates, log}`。
- 文件：吸收 build_new_dataset.py 的清洗部分，规则从写死改为配置注入。
- TBD：候选阈值默认值表（p95、切换次数上限、方差尖刺判据）。

### ⑤ Observation 处理

- 输入：样本清单 + 原始视频/状态。
- 输出：模型输入表示 + 变换配置（可复现）。
- 接口：`build_observation(frames, transform_config) -> tensors`。
- 文件：吸收 openpi_patch 的 transform；变换配置进 provenance。
- 约束：保留原图；可分性标注以**处理后表示**为准（框架 §3 语义判据）。
- **遥操 ↔ 模型输入的 gap（开放问题）**：操作员的动作基于其实际可用的信息，
  模型只有处理后相机+状态。gap 构成：
  (a) 信息不对称——操作员肉眼/全视场看到的信息，相机里没有；
  (b) 表示差异——操作员看原始分辨率，模型看缩放后输入，细节可能丢失；
  (c) 反应时延——动作是对 t−δ 观测的响应，标签与观测存在错位；
  (d) 力觉/触觉——操作员有力反馈，模型无此通道。
  候选诊断方向（无成熟方案，见 `../../issues.md` ISSUE-002）：探针不可学性分析
  （= 可分性标注的泛化：用处理后观测预测动作，失败段即 gap 段）；采集侧
  注意力标注（记录操作员当时看显示器还是直接视野）；时延估计与标签平移
  （仅限自由段，事件段禁止）。
- TBD：视频重编码（-g 2）是否仍在此模块执行；gap 的诊断与缓解方案。

### ⑥ Action 标签构建

- 输入：样本 + 标签配置（A 类旋钮：span_frames/action_horizon/event_points/
  key_weight/approach_frames）+ 语义标注（B 类旋钮输出：事件窗定义注入）。
- 输出：action_chunk 列 + action_loss_weight 列 + **消费契约声明**。
- 接口：`build_labels(states, actions, config, annotations) -> {chunk, weight, contract}`。
- 文件：吸收 progress_resample.py（核心算法不动）；事件窗定义从"命令沿+
  真空反馈"改为**判据注入**（agent 输出的事件区间直接作为 dwell/approach
  mask 输入）。
- 关键改动点（**关键帧判定 = 语义 ∧ 可分**）：关键帧的定义本身是语义判据
  （"任务关键时刻"，B 类旋钮），且必须满足"该帧观测可用"。EEF 状态变化发生
  时若观测被遮挡，**该帧不作关键帧**，权重迁移到最近的、观测可用的帧
  （其 chunk 仍覆盖事件时序）。落点规则：key_weight 落在"事件窗内且可分"的
  源帧上（旋钮 4 推论；待测量确认后启用）。
- TBD：事件窗判据注入的接口形态（mask 数组 vs 判据函数）。

### ⑦ 数据集划分与统计

- 输入：样本清单。
- 输出：划分清单（episode 级）+ norm stats。
- 接口：`split(sample_list, split_rule) -> {train/val/test}`；
  `norm_stats(dataset) -> stats`（吸收 compute_arc_norm_stats.py）。
- 约束：划分规则早定、写进 provenance；增强副本随源 episode 同划分。
- TBD：默认划分规则（episode 级随机比例 vs 场景级 held-out，GAP-09 无文献
  可依，需自定并验证）。

### ⑧ 可选增强与文本生成

- 输入：样本 + 增强配置。
- 输出：增强样本 + 对应关系 + 覆盖检查。
- 约束清单（框架 §3）：保任务语义；时序增强禁止压缩事件驻留；速度类增强
  仅限无接触段；生成轨迹按 MimicGen 范式验证（成功过滤+覆盖检查）。
- 文件：新增 `augment.py`（起步仅 color jitter + 随机 crop，对应 DROID 先例）。
- TBD：文本改写（prompt 多样性）的规则集与"不得加入事后信息"的检查方式。

### ⑨ 格式导出与模型适配

- 输入：数据集工件。
- 输出：LeRobot v2.1 格式（版本钉死）+ 模型输入输出映射。
- 文件：吸收 export_hf.py、openpi_patch（config/transform/register）。
- TBD：无（沿用现有）。

### ⑩ 验收与覆盖分析

- 输入：数据集 + provenance。
- 输出：验收报告（模型输入级检查）+ 缺口分析 + 补采建议。
- 文件：吸收 verify_dataset.py（6 项）+ probe_arc_batch.py（端到端探针）；
  新增覆盖矩阵（任务×场景×视角×事件类型）。
- 补采建议格式（仿 RoboMIND）：缺口定位（哪个任务/场景/视角的哪类样本缺失）
  + 原因 + 建议量级；区分"缺样本/缺视角/缺传感器/模型能力不足"四类。

## 3 离线指标工具清单

| # | 指标 | 定义 | 输入 → 输出 | 无训练 | 用途 |
|---|---|---|---|---|---|
| M1 | 重建误差对比 | 标签点 PCHIP 重建 vs 原始轨迹，末端 mm | 标签+轨迹 → 误差曲线 | ✓ | 广度过滤 |
| M2 | 浪费点占比 | 分配在语义次优段上的点数 / H | 标签+次优标注 → 比例 | ✓ | 旋钮 2 基线 |
| M3 | 事件窗可分性分布 | 视觉邻居一致性（处理后表示） | 样本+表示 → 每帧可分性 | ✓ | key_weight 检查 |
| M4 | oracle 回放碰撞率 | 重建场景回放轨迹的碰撞数 | 场景+轨迹 → 碰撞报告 | ✓ | real2sim 自检 |
| M5 | 统计离群 | 时长/方差尖刺/切换次数 | 数据集 → 候选列表 | ✓ | 清洗候选 |
| M6 | 覆盖矩阵 | 任务×场景×视角×事件计数 | 标注 → 矩阵 | ✓ | 缺口分析 |

吸收映射：M1 ← keypoint_budget.py/eef_error.py；M5 ← noise_floor.py/
dataset_review.py；其余新增。**指标工具与 agent 解耦**：stdin/args 输入、
JSON 输出，可独立运行（框架 §3.4 简化原则）。

## 4 agent 工具清单

- 数据访问工具：读帧（处理后表示）、读状态、读标注。
- 指标工具：M1–M6（function call 包装）。
- 配置工具：读/写 A 类旋钮（写操作需记录理由进 provenance）。
- 输出：结构化判断对象 `{对象定位, 判断类型, 结论, 理由, 置信度, 建议动作}`；
  建议动作类型枚举：过滤候选/加权调整/预算调整/标注写入/补采建议。
- TBD：agent 框架选型（直接 function call vs DSPy 类编排）——起步建议直接
  function call，编排复杂度确有需要再引入 DSPy。

## 5 双指标搜索的指标定义

- 广度指标（每配置必跑，全离线）：M1 重建误差 p95、M2 浪费点占比、
  M3 可分性分布、M4 碰撞率。
- 校准指标（抽样跑，需训练）：下游策略成功率（任务级）。
- 搜索空间：A 类旋钮边界表（TBD；初始 = 现有 8 参数的 ± 范围：
  span_frames 100–400、event_points 8–64、key_weight 1–5、approach_frames
  5–30 等）。
- 结果矩阵 schema：`{配置哈希, 各广度指标, 下游成功率(若有), 时间戳, 决策记录}`。
- 回路：广度过滤 → 下游校准（周期 TBD，建议每 N 轮或每 X 配置）→
  agent 分析取舍 → 下一轮候选。

## 6 验证回路

- 三臂对比（OPT-001 证据 1）：同数据 ×（纯几何 / 几何+语义过滤 /
  几何+语义加权）→ 同策略训练 → 成功率对比 + 成本记录。
- oracle 自检（OPT-002 证据 1）：重建场景回放原始轨迹，碰撞 = 0 方可启用。
- 人审机制：agent 产出的删除/过滤候选，抽样（TBD 比例）人工复核后执行。
- 修订回路：下游结果 → 改判据/规则（进 provenance）。
