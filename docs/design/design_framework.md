# 数据处理 Agent：设计框架

> 初步设计：框架分层与接口。具体设计（每模块的接口、文件、工具清单）另行展开。

## 1 数据预处理顶层流程（L0）

十模块骨架，不含方法：

| # | 模块 | 职责 | 关键产出 |
|---|---|---|---|
| ① | 数据定义与接入 | 字段语义、单位、坐标系、机器人/任务身份、格式版本 | 数据字段说明 |
| ② | 完整性检查与时间对齐 | 缺帧/重复/时钟偏移；多路流对齐；事件窗对齐检查 | 对齐数据+有效性标记 |
| ③ | 分层标注与质量诊断 | 任务/异常/冗余标注（处理前）；可分性标注（观测处理后） | 标注+证据 |
| ④ | 清洗与样本选择 | "候选+解释"原则：保留/隔离/裁剪，不静默删 | 样本清单+处理记录 |
| ⑤ | Observation 处理 | 图像/状态/历史表示；变换可复现；保留原图 | 输入表示 |
| ⑥ | Action 标签构建 | chunk、重采样、事件保护、权重；声明消费契约 | 标签+契约 |
| ⑦ | 数据集划分与统计 | 划分规则早定（episode 级）；norm stats 在表示确定后算 | 划分清单+统计量 |
| ⑧ | 可选增强与文本生成 | 受约束的多样性；需验证与覆盖检查 | 增强策略+对应关系 |
| ⑨ | 格式导出与模型适配 | 输出指定格式版本，映射模型输入输出 | 可加载数据集 |
| ⑩ | 验收与覆盖分析 | 模型输入级检查；缺口分析 | 验收报告+补采建议 |

贯穿规则：provenance（每个决策记录判据与配置）贯穿所有模块；消费契约是
⑥ 的产出物，是管线与部署侧的接口。

## 2 现有 benchmark 顶层管线（L1）

| | 定义 | 对齐 | 标注 | 清洗 | 标签 | 验收 |
|---|---|---|---|---|---|---|
| LeRobot | 格式最标准 | 有接口 | ✗ | 弱 | 默认等时 | 社区自理 |
| DROID | 完整 | 标定级 | 人工+GPT-4V | 多层 | 默认 | 弱 |
| AgiBot | 完整 | 缺帧校验 | 人工 | 人工核对 | 默认 | 无 |
| RoboMIND | 完整 | 未涉及 | Gemini+人工 | QA 清单 | 默认 | 弱 |
| 现有包 | 完整 | 事件窗对齐 | ✗ | 写死规则 | 最强 | 自制 6 项 |

总结：所有人的骨架一样，差异全在"判据由谁定"——写死规则（现有包）、
人（DROID/AgiBot）、LLM 半自动（RoboMIND）。没有任何 benchmark 有
"旋钮调节者"。

## 3 旋钮体系（L2）

### 3.1 旋钮两分

- **A 显式参数旋钮**（数值型，直接可调）：清洗阈值（p95、离群判据、方差
  尖刺阈值）、标签预算（span_frames、action_horizon、event_points、
  key_weight、approach_frames）、分辨率、划分比例、增强强度、norm stats
  口径。
- **B 语义判据旋钮**（定义型，task 相关）：关键事件定义（吸盘触发只是
  特例）、稀疏点取舍（哪些 action 点是冗余）、次优帧判据（绕路/犹豫，
  非停顿）、观测可分性判据。输出形态 = 判据定义 + 逐段标注 + 理由。
- 工程类旋钮（格式版本、划分规则、消费契约）= A 的特例，人定死，不参与优化。

四旋钮（事件泛化 / 次优段饿死 / 事件预算 / 可分性标注）= B 类中第一批
被识别的高价值实例，不是全集。
关键帧判定 = 事件定义 ∧ 可分性判据的合成（二者缺一不可）：EEF 状态变化
发生时若观测被遮挡，该帧不作关键帧，权重迁到最近可分帧。

### 3.2 agent 能力三层次

1. **调节（set）**：直接输出旋钮值/判据定义。
2. **搜索（search）**：编排脚本跑配置扫描，产出结果矩阵。
3. **分析（analyze）**：解释结果矩阵、做取舍、提出下一轮搜索方向。

### 3.3 双指标搜索模式

- 便宜指标（全离线，无训练）→ 铺广度，快速过滤差配置：
  稀疏点重建对比（标签 vs 重建）、浪费点占比、事件窗可分性、
  oracle 回放碰撞率。
- 下游验证（训练+成功率）→ 校准，周期性抽样验证便宜指标的可靠性。
- 两个指标各司其职，不互相替代。

### 3.4 简化原则

- 多数指标无需训练即可测量，全离线。
- 离线脚本与 agent 无关，只向 agent 暴露接口。
- 整体复杂度：agent = 薄决策层 + 现成离线指标工具 + 配置搜索编排。

## 4 agent 顶层设计（L3）

### 4.1 功能需求层（agent 做什么）

与 §3.2 的能力三层次对齐：

1. **调节（set）**：给出语义判据与旋钮值——诊断、判断、解释、提议均
   归属于此（每条判断附理由与建议动作），并根据验证反馈修订；
2. **搜索（search）**：编排配置扫描脚本，产出结果矩阵；
3. **分析（analyze）**：读结果矩阵、做取舍、提出下一轮搜索方向。

### 4.2 系统接口层（agent 与外界怎么接）

- 感知接口：读观测（视频 clip / 状态序列 / 指标曲线）；
- 工具接口：调确定性工具（离线指标、碰撞、统计），function call 形式；
- 知识接口：读规则层（数据定义、事件判据、QA 标准、稳态约束）；
- 人接口：例外上报、结果确认；
- 状态接口：读写工件（标注、结果矩阵、provenance）。

### 4.3 约束层

- 只提议不删除（第一阶段）；
- 所有判断需理由、可溯源；
- 成本预算；
- 判断结果以"候选+解释"形态交付，删除需验证条件满足。

### 4.4 状态层（工件）

- 已标注集（标注列）；
- 结果矩阵（配置扫描记录）；
- 判据历史与决策记录。

## 5 agent 输入输出形式（L4）

### 5.1 输入包

- 任务上下文：task 定义、事件判据、QA 标准、稳态约束（规则层内容）；
- 样本：视频 clip（模型输入表示）、状态序列、既有指标曲线；
- 工具返回：离线指标结果、碰撞报告、统计量；
- 可选：人工反馈（边缘案例裁定）。

### 5.2 输出

- 结构化判断对象：
  `{对象定位: 帧区间/点集, 判断类型: 事件/次优/冗余/可分性/配置建议,
  结论, 理由, 置信度, 建议动作}`；
- 工具调用请求（function call）；
- 报告：缺口分析、取舍分析、补采建议。

### 5.3 落盘形态

- 标注列（parquet 新列）+ provenance 记录（判据+配置+理由）
  + 结果矩阵（CSV）。
