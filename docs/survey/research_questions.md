# 研究问题

## 背景

现有管线（`reference/g2-orion05-resample-training/`）用纯几何量（关节曲率 `|q''|^(1/3)`、
事件窗时间保护、关键帧加权）对遥操数据的动作标签做稀疏重采样。收益是停顿自动
失去监督密度；缺陷是**遥操的次优解无法去除**——次优轨迹在几何上与最优轨迹
不可区分。方向假设：用 agent 做语义级理解，识别并去除一部分次优解。
本调研为该方向提供事实基础。

## 范围与证据标准

**纳入**：机器人学习/遥操数据管线（清洗、过滤、重采样、标注、加权）的公开
论文与技术报告；LfD 与运动基元的轨迹处理经典方法（不限年份）；演示质量评估
与次优演示过滤；语义/语言/VLM 用于机器人数据标注与筛选的先例；LLM agent
权威综述与基础方法（2022 起）；agentic data curation / LLM-as-judge / 自动数据
优化；机器人领域 agent/语义数据管线的具体系统。

**排除**：纯 RL 训练与 replay buffer 方法（仅在与演示过滤相邻处提及）；纯仿真
数据生成与 sim-to-real 迁移；模型架构与训练算法改进本身；商业闭源产品评测；
prompt engineering 与 MCP 协议实现细节；agent 部署优化（量化、加速）。

**证据等级**：direct（直接回答 RQ）；indirect（研究相邻机制）；weak（只提供
背景、指标或方法启发）；irrelevant（归档但不抽取）。

**来源**：主 arXiv API，辅 Semantic Scholar API（记录于 `logs/search_log.md`）。

**时间范围**：agent 相关 2022 起；数据管线以 2023 起为主；LfD 经典不限年份。

## RQ1 机器人数据预处理范式

**RQ1 主问题**：机器人控制/机器人学习领域的数据预处理（清洗、过滤、重采样、
标注、加权）是否存在公认的常见方法或标准流程（范式）？

**RQ1.1** 机器人学习（vision-action / VLA 模型）社区的数据管线标准做法是什么？
有哪些步骤（录制、清洗、过滤、重采样、标注、加权）？各步骤的代表方法与工具？

**RQ1.2** 经典示教学习（Learning from Demonstration）与运动基元领域，对
演示轨迹有哪些预处理方法：轨迹分割、关键帧提取、时间对齐、平滑降噪？
这些方法与现有曲率重采样是什么关系？

**RQ1.3** 数据质量过滤：现有方法如何识别、评分、过滤低质量或次优演示？
（成功/失败检测、质量打分、偏好过滤、自动过滤等。）

**RQ1.4** 语义级/语言级数据处理先例：有没有用语言模型/VLM 对机器人数据进行
语义标注、理解、筛选的先例？这是 agent 方案的直接上游证据。

## RQ2 Agent 基础与 agentic 数据策展

**RQ2.1**（教学）LLM agent 的定义、组成（规划、工具、记忆）、典型运行方式

**RQ2.2** agent 用于数据策展/数据处理/数据优化的现有方法：
agentic synthetic data、LLM-as-judge、DSPy/TextGrad 类自动优化、
指令与数据生成类工作。

**RQ2.3** 机器人领域的语义数据管线先例：用 VLM/LLM/agent 对机器人轨迹/episode
做语义理解、标注、过滤、重标记的具体工作。

**RQ2.4** 工程模式：离线批量数据管线中 agent 的架构模式（批量推理、工具设计、
成本控制、验证回路），以及与传统确定性管线如何结合。

## RQ4 动作模态对齐（2026-09-08 收束后的主动研究方向）

**背景（收束决策，见 `logs/decision_log.md` 2026-09-08）**：总目标 = vision /
language / action 三模态对齐，action 序列视作一种模态。纯几何重采样会破坏
对齐（跳帧、压低必要停顿）；研究方向转为"找到与 vision / 文本 prompt 对齐
的 action 模态增强方式"。本组问题取代 RQ2（agent 方向，标记为 superseded）。

**RQ4.1 跨模态对齐方法**：vision-text、text-action、vision-action 及其它模态
（本体感受、真空反馈）的对齐学习范式；action 作为模态的跨模态表征学习
（对比、掩码、匹配）。

**RQ4.2 动作表征空间**：action 序列如何编码进与 vision/text 共同的空间
（tokenizer / 量化 / embedding / latent）；动作本身低秩而 action 序列高维的
含义（subspace / 流形维度）。

**RQ4.3 动作模式结构**：可识别模式——流形、聚类、函数簇；"一条指令对应
一类同构 action 序列簇"的证据；指令-模式对应（语言条件切分/事件边界，
衔接 [paper_035](https://arxiv.org/abs/2309.00743) / [paper_011](https://arxiv.org/abs/2603.01465)）。

**RQ4.4 对齐度量**：如何度量 action 模态与 text/vision 的对齐（互信息、
InfoNCE 类、DTW 类时序相似度、表征对齐）；与既有 H(ℓ|v)（可见的跨模态
冗余度量）的关系。

**RQ4.5 跨本体 / sim→real 动作迁移**：对齐后"良好但不可直接迁移"的 action
label 的复用（统一动作空间、域适应、不变特征）；与 OPT-002 复活后的关系。

**RQ4.6 时序结构与保真**：驻留/停顿/事件驻留的对齐语义；时间规整（DTW 类）
在动作对齐中的作用（衔接 GAP-01）。

**RQ4.7 生成/增强保对齐**：生成式（diffusion/flow）action 建模、动作增强
如何保持对齐；增强的验证方式（衔接 MimicGen 教训）。

## RQ3 数据管线模块级问题

背景：数据预处理是完整 pipeline（数据定义 → 对齐 → 标注 → 清洗 →
observation 处理 → action 标签构建 → 划分与统计 → 增强 → 导出 → 验收）。
文献库对以下模块级问题覆盖不足，追加本组问题。

**RQ3.1** 训练/验证/测试划分规则：episode 级划分与泄漏控制的证据；
数据增强副本的泄漏问题；held-out 场景/任务的 OOD 验证惯例。

**RQ3.2** 多传感器时间同步与时间戳对齐：曝光时刻 vs 接收时刻、跨相机同步、
action/state 时戳语义；遥操数据集中的对齐实践。

**RQ3.3** 机器人学习数据增强的安全性：flip/crop/时序/语言改写各增强的
边界条件与失败模式；轨迹级增强（如 MimicGen）的验证方式。

**RQ3.4** 观测可分性（state aliasing）标注：单帧观测不可分的检测与标注
先例；与 GAP-08 对应。

**RQ3.5** 覆盖分析与补采建议：gap-driven 数据采集的判据与产出形态
（语言/视觉多样性、失败归因、场景覆盖）。
