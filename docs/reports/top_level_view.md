# 顶层视角：五个面

> 本文件是项目的**思维地图**。目标：把讨论中反复出现的概念按面分开，
> 防止不同层次的东西混在一起。每个面只回答一个问题；面与面之间只有
> 一条连接规则（见 §6）。详细论证见 `docs/reports/discussion_report.md`。

## 1 问题面：三个正交轴（回答"在解决什么"）

| 轴 | 攻击的问题 | 机制 | 状态 |
|---|---|---|---|
| 几何轴 | 表示误差（多少个点重建得准） | 曲率重采样 `|q''|^(1/3)` | 已有（训练中） |
| 语义轴 | 演示质量（这条轨迹该不该学） | agent 四旋钮 | 新增（待设计） |
| 物理轴 | 可行性（修改后的轨迹会不会撞） | real2sim 静态碰撞 oracle | 新增（待设计） |

规则：**一轴一机制，互不替代**。几何看不见质量；语义不能生成路径；
物理不能判断好坏。三者合成："语义提方案、几何生成、物理裁决"。

## 2 系统面：四层运行时栈（回答"系统怎么搭"）

```
规则层（人写、声明式、可审计、版本化）
  数据定义 / QA 标准 / 事件判据 / 稳态假设及其边界
    ↓ 指导
决策层（VLM/LLM + 批评者）
  判断、解释、提议；四个旋钮在此实现
    ↓ 调用
执行层（确定性工具，全部可复现）
  时间对齐 / 曲率重采样 / 碰撞检测 / 过滤 / 格式导出
    ↓ 产出
验证层（反馈，向上流）
  oracle 自检 / 下游三臂对比 / 人审边缘案例
```

反馈方向是定义性的：验证层的产出必须能改决策层甚至规则层
（Demo-SCORE 的 rollout 训分类器、AgiBot 的策略评估修订采集协议）。

## 3 流水面：十模块管线（回答"数据流经哪些步骤"）

```
定义 → 对齐 → 标注 → 清洗 → 观察 → 标签 → 划分 → 增强 → 导出 → 验收
```

- 十模块是**执行层的流水线形态**，不是独立于系统面的另一套东西。
- 四个旋钮是决策层注入流水线的四个接口点：
  - 旋钮 1（事件泛化）→ 注入"标注"与"标签构建"；
  - 旋钮 2（次优段饿死）→ 注入"清洗"与"标签构建"的权重；
  - 旋钮 3（事件预算）→ 注入"标签构建"参数；
  - 旋钮 4（观测可分性）→ 注入"标注"（输出可分性标签，在观察处理后算）。
- real2sim oracle → 服务于"清洗/样本选择"（过滤）与"标签构建"（捷径替换）。

## 4 消费面：部署契约（回答"标签被谁怎么吃掉"）

- 数据侧**声明**：标签不等时（点距跨越 15 倍）、PCHIP 构建、事件窗时间保护、
  21.7% 集尾钳制。
- 运控侧**实现**：dt_min 调度 + C1 插值 + smoothstep 融合 + jerk 限幅。
- 契约是管线（执行层）与部署侧之间的接口，必须显式声明（现有包 §6 已做）。
- 稳态假设保证：消费侧的时间参数化自由度只在事件窗外存在。

## 5 过程面：项目节奏（回答"我们按什么顺序走"）

```
证据（35 篇，已完成）→ 基线测量（0a 浪费点占比 / 0b 事件窗可分性）
→ 管线设计（plan.md）→ 三臂对比（下游验收）→ 专利评估（最后）
```

- 基线测量不需要训练、不需要 VLM；它们回答"问题是否存在"与"现有管线是否
  已踩雷"。
- 专利属于过程面最后一步，不属于系统本身。
- 文献资产（../../papers/、../../synthesis/）属于过程面，为每一步提供证据。

## 6 唯一连接规则

1. 十模块 ⊂ 执行层（流水线形态）；
2. 四旋钮 = 决策层注入流水线的四个点；
3. 三轴 = 各机制的动机（一个机制攻击一个轴）；
4. 验证层 = 唯一终审（一切过滤/加权/捷径以下游策略成功率验收）；
5. 消费契约 = 管线与部署侧的接口；
6. 过程面 = 系统的建造顺序，不是系统的一部分。
