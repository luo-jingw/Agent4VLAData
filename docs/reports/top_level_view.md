# 顶层视角：五个面

> 本文件是项目的**思维地图**：把概念按面分开，防止不同层次的东西混在一起。
> 每个面只回答一个问题；面与面之间只有一条连接规则（见 §6）。
> 详细论证见 `docs/reports/main_report.md`。

## 1 管线面：十模块数据流程（顶层骨架）

```
定义 → 对齐 → 标注 → 清洗 → 观测 → 标签 → 划分 → 增强 → 导出 → 验收
```

- **顶层结构 = 管线本身**。旋钮、agent、验证都以模块为落点。
- 纯几何曲率重采样是 **⑥ 标签构建**模块内的一种机制，与事件窗判据、清洗
  规则同级，不是顶层设计的一部分。
- 机制分工（为什么需要不同机制）：几何管表示误差（⑥ 内）、语义管演示
  质量（③④ 的判据）、物理管可行性（验证面）——分别服务于不同模块的旋钮。
- ⑥ 的产出附**消费契约**：数据侧声明不等时标签 + PCHIP + 事件窗时间保护；
  运控侧实现 dt_min + C1 插值 + smoothstep + jerk 限幅。

## 2 旋钮面：两类旋钮（每个模块都要"决定"的东西）

- **A 显式参数**（数值型）：清洗阈值、标签预算、分辨率、划分比例、增强强度。
- **B 语义判据**（定义型）：关键事件定义、次优帧判据、冗余点取舍、观测可分性。
- 旋钮属于模块，不属于 agent；人与 agent 都转这些旋钮。
- 四个旋钮 = B 类中第一批高价值实例：
  - 旋钮 1（事件泛化）→ 注入"标注"与"标签构建"；
  - 旋钮 2（次优段饿死）→ 注入"清洗"与"标签构建"的权重；
  - 旋钮 3（事件预算）→ 注入"标签构建"参数；
  - 旋钮 4（观测可分性）→ 注入"标注"（在观测处理后计算）。

## 3 决策面：agent（调节 / 搜索 / 分析）

- **调节**：直接输出旋钮值/判据定义，每条附理由；
- **搜索**：编排脚本跑配置扫描，产出结果矩阵；
- **分析**：读结果矩阵、做取舍、提出下一轮搜索方向。
- **规则层**（人写、版本化）：数据定义、QA 标准、事件判据、稳态假设及其
  边界——是 agent 的输入约束；agent 只提议，删除需验证条件满足。

## 4 验证面：反馈（向上流）

- **物理 oracle**：几何可行性（静态碰撞检测，real2sim），服务于清洗过滤与
  标签捷径替换；动力学限幅（速度/加速度/力矩）为后续 kinodynamic gate；
- **下游三臂对比**：一切过滤/加权/捷径的终审；
- **人审边缘案例**。
- 反馈必须能改决策面甚至规则层（rollout 结果训分类器、策略评估修订采集协议
  等先例）。

## 5 过程面：项目节奏

```
证据（35 篇，已完成）→ 基线测量（0a 浪费点占比 / 0b 事件窗可分性）
→ 管线设计（plan.md）→ 三臂对比（下游验收）→ 专利评估（最后）
```

- 基线测量不需要训练、不需要 VLM；它们回答"问题是否存在"与"现有管线是否
  已踩雷"。
- 专利属于过程面最后一步，不属于系统本身。
- 文献资产（`../../papers/`、`../../synthesis/`）属于过程面，为每一步提供证据。

## 6 唯一连接规则

1. 管线是骨架；旋钮挂在模块上；
2. agent 与人都转旋钮；agent 覆盖调节/搜索/分析三层次；
3. 曲率重采样是 ⑥ 内的一种机制，与事件窗判据、清洗规则同级；
4. 验证面是唯一终审（一切过滤/加权/捷径以下游策略成功率验收）；
5. 消费契约是 ⑥ 的产出接口，连接管线与部署侧；
6. 过程面是系统的建造顺序，不是系统的一部分。
