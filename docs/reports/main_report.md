## 0. 摘要

1. **现状**：我们有一条已训练的纯几何管线（曲率重采样）。它解决了"停顿偷走
   监督预算"，解决不了"次优解"——次优轨迹在几何上与最优轨迹不可区分【证据】。
2. **调研结论**（35 篇文献）：机器人数据预处理在**步骤层**有共识范式、
   **判据层**没有；语义级数据处理有先例但无下游验证【证据】。
3. **最重要的负面证据**：离线评分指标与下游策略收益**脱钩**（两篇独立工作）；
   本轮纳入文献中唯一带下游定量验证的策展接的是"执行反馈"【证据】。
4. **我们的定位**：agent 不做"过滤器"（易脱钩），做**语义旋钮的调节者**
   ——四个旋钮，每个都有可测指标【推理】。
5. **任务约束让 real2sim 变便宜**：静态场景下"碰撞检验"就是最硬的执行反馈，
   与语义方案互补："语义提方案、几何生成、物理裁决"【约束+推理】。
6. **建议路径**：先两个无训练基线测量 → 管线设计 → 受控对比；专利评估放在
   证据之后【推理】。

## 1. 背景：我们站在哪里

### 1.1 现有方法（三句话）

把遥操录制的稠密动作序列，按**曲率密度**（`|q''|^(1/3)`）稀疏取点重建成
动作标签：拐弯处点密、直线处点疏；吸盘触发前后的事件窗**按时间**保护
（真空建立是物理时长）；事件窗内的点在损失里乘 3 倍权重。
观测帧全部保留，只有标签内部的动作序列被重采样【约束，来自现有方法包】。

### 1.2 它的能力边界（为什么需要新东西）

| 问题类型 | 几何管线能否处理 | 原因 |
|---|---|---|
| 停顿/犹豫 | ✓ 已解决 | 曲率为零 → 自动失去标签密度 |
| **绕路/次优轨迹** | ✗ 且**反而更糟** | 绕路=拐弯=高曲率 → 曲率密度**主动把点分给绕路**，次优解偷走点预算 |
| 无 EE 切换的关键事件 | ✗ | 事件窗靠"吸盘命令沿+真空反馈"定位；插入 U 盘类任务没有这个切换 |
| 关键窗口观测失效 | ✗ 可疑 | 吸盘贴近工件时腕相机看不到有效信息，却拿着 3 倍权重（待测） |

【推理】三、四行由几何公式与管线实现直接推出；第四行的"待测"见 §4.2 旋钮 4。

### 1.3 任务约束（详见 PROJECT.md）

- **静态场景**：料箱/传送带静止；唯一会动的是被吸的工件（搬运段刚性附着末端）。
- **稳态假设**：路径几何一致 + 吸盘状态切换驻留时间一致 ⇒ 成功；
  在部署调度包络内（相对录制时长 0.78–1.08×）速度变化不影响成功率，
  超出包络需动力学限幅检查。
- **边界条件**：速度无关性只在**无接触动力学**的段成立；
  接触/力控任务中速度变化会改变环境反应（真实反应 vs 时间缩放复制 88% vs
  31%）【证据，[paper_026](https://arxiv.org/abs/2412.03252)】。我们的吸盘任务符合无接触段假设；
  扩展到力接触任务前必须重新验证。

## 2. 逻辑主线（为什么是 agent，为什么这样设计）

> 本节是全文论证的骨架。每步标注依据类型。

**第 1 步：目标定义。**
数据预处理的目标 = 给模型"可学习、低噪声、保时序"的监督信号。（定义）

**第 2 步：表示误差与演示质量是两个正交问题。**
曲率重采样（管线 ⑥ 标签构建内的一种机制）只能优化"表示误差"（用多少个点
能把轨迹重建得准）；次优解属于"演示质量"（这条轨迹该不该学）。几何量看不到
质量，次优轨迹的曲率特征与最优轨迹不可区分【推理，由 §1.2 表推出】。

**第 3 步：语义判断需要 agent 形态的系统。**
"这段绕路了""这个事件是插到位""这个观测看不到工件"——这类判断需要能看
视频/轨迹、理解任务的系统。文献中的形态是 VLM/LLM：OpenGVL 用 VLM 预测逐帧
任务进度策展数据【证据，[paper_010](https://arxiv.org/abs/2509.17321)】；AutoRT 用 LLM 生成任务+自我批评
过滤，7 个月采集 77k episode【证据，[paper_019](https://arxiv.org/abs/2401.12963)】。

**第 4 步：但语义打分有脱钩风险。**
两篇独立工作证明：检测缺陷的离线指标（几何/统计/分阶段）与下游策略收益
**脱钩**——检出 AUROC 与下游成功率 Spearman 相关 ρ=−0.14，AUROC 最高的指标
下游最差【证据，[paper_005](https://arxiv.org/abs/2606.10229)】；分阶段局部化策展全面失败【证据，[paper_014](https://arxiv.org/abs/2606.15064)】。
本轮纳入文献中唯一带下游定量验证的策展用"在线 rollout 的成功/失败"做判据，仿真 +15–35%、
真实 +15–40%【证据，[paper_013](https://arxiv.org/abs/2503.03707)】。

**第 5 步：由此推出设计原则。**
(a) agent 的每个决策旋钮都必须有**下游可测指标**兜底，不能只做检出评估；
(b) 静态场景使"碰撞检验"成为**廉价且客观**的执行反馈形态（比 rollout 便宜
几个数量级）【约束+推理】；
(c) agent 管判断、确定性工具管执行、下游策略成功率管验收【推理】。

**第 6 步：总设计一句话。**
**"语义提方案、几何生成、物理裁决、下游验收"** —— agent 指出哪里有问题、
为什么（旋钮 1/2/4）；几何/物理工具生成修复或验证（OPT-002 real2sim）；
三臂受控对比给出最终裁决（§6）。

## 3. 调研发现

### 3.1 数据处理有没有范式？（RQ1）

**步骤级有、判据级没有。** 各大项目的数据流程高度一致：

```
记录 → 校验 → 标注 → 过滤 → 格式标准化 → 标签重采样/增广
```

（DROID、AgiBot World、LeRobot 均可佐证【证据，[paper_001](https://arxiv.org/abs/2403.12945)/[paper_015](https://arxiv.org/abs/2503.06669)/[paper_004](https://arxiv.org/abs/2602.22818)】）
但过滤阈值、质量标准、标注体系全是各家自定，没有跨项目标准【证据】。
工具链已收敛到 LeRobot 格式【证据，[paper_004](https://arxiv.org/abs/2602.22818)】；质量环节没有成熟工具。

### 3.2 agent 是什么（教学级，30 秒版）

Agent = **以 LLM/VLM 为决策核心 + 可调用工具 + "思考→行动→观测"循环**的系统
【证据，[paper_006](https://arxiv.org/abs/2309.07864)/[paper_007](https://arxiv.org/abs/2210.03629)】。普通 LLM 调用是一问一答；agent 把模型放进
循环里，每步决策基于上一步的环境反馈。其价值（把推理接到外部世界上）与
代价（推理错误率上升、每步都是模型调用）都有定量证据【证据，[paper_007](https://arxiv.org/abs/2210.03629)】。
对我们的场景，最省事的理解：**agent = 会循环的 VLM + 分析工具 + 可积累的
判断记录**。详细教程见 `docs/survey/agent_basics_tutorial.md`。

### 3.3 管线模块级证据（第三轮，9 篇新增）

| 模块 | 关键发现 | 依据 |
|---|---|---|
| 训练/验证划分 | episode 级划分是"实践共识、文献沉默"；组合泛化 held-out 有先例 | [paper_030](https://arxiv.org/abs/2412.13877)/[paper_031](https://arxiv.org/abs/2606.16826) |
| 时间戳对齐 | 遥操数据集同步实践无专文；可借鉴 SLAM 域时间偏移估计 | [paper_016](https://arxiv.org/abs/2505.15558)/[paper_032](https://arxiv.org/abs/2201.09170)（weak） |
| 数据增强 | 轨迹级增强用"真实执行+成功过滤"验证；速度类增强有接触边界；naive 成功过滤有覆盖偏置 | [paper_024](https://arxiv.org/abs/2310.17596)/[paper_026](https://arxiv.org/abs/2412.03252) |
| 观测可分性 | 状态歧义五类分类已有；但全部走模型侧方案，**本轮文献未发现数据标注** | [paper_029](https://arxiv.org/abs/2512.24638) |
| 覆盖与补采 | "失败案例→数据短板→补采建议"是成熟形态 | [paper_030](https://arxiv.org/abs/2412.13877) |

详见 `docs/survey/survey_findings.md`。

## 4. 方案：对齐判据 + 验证回路（收束后；原四旋钮降级为对齐度表现之一）

### 4.1 旋钮总表

| # | 旋钮 | 回答的问题 | 最便宜的验证 | 文献状态 |
|---|---|---|---|---|
| 1 | 事件泛化 | 关键事件在哪（不止 EE 切换） | VLM 标注 5-10 样本，人工抽查 | 本轮文献未见先例（训练检测器有：[paper_011](https://arxiv.org/abs/2603.01465)） |
| 2 | 次优段饿死 | 哪些段在偷点预算 | 浪费点占比基线（无训练） | GAP-03，空白 |
| 3 | 事件预算自适应 | 每类事件该给多少点 | 旋钮 1 的参数延伸 | 本轮文献未见先例 |
| 4 | 观测可分性标注 | 哪些帧的观测根本没信息 | 视觉条件动作歧义度（纯离线） | GAP-08，本轮文献空白（歧义分类法可借用 [paper_029](https://arxiv.org/abs/2512.24638)） |

### 4.2 每个旋钮的问题-机制-指标

**旋钮 1（事件泛化）**。现有事件 = 末端执行器命令沿 + 真空反馈，本质是
"准静态假设破裂处"的代理。插入 U 盘类任务的关键事件是**空间接触事件**，
没有 EE 切换，现有规则失明。agent 检测"驻留关键事件"，EE 切换只是特例。
收益：训练侧事件窗定义泛化（零样本、任务级、可解释）；推理侧 dt_min 时间
保护同步泛化【推理】。

**旋钮 2（次优段饿死）**。`ds ∝ |q''|^(1/3)` 使绕路（高曲率）**主动消耗点
预算**。指标：每 episode"浪费点占比" = 分配在 agent 标记次优段上的点数 / H。
介入前 X% → 介入后 Y%，下游成功率不降【推理，由 §1.2 推导】。

**旋钮 3（事件预算自适应）**。event_points=32、approach_frames=15 现为全局
常量（半数事件窗只有 16 帧长，预算被窗长钳制【证据，现有方法包】）。agent 按
任务/事件类型分配预算。实现代价最小（只动参数不动结构），适合作为 agent 的
**第一个落地旋钮**【推理】。

**旋钮 4（观测可分性标注）**。关键窗口（吸盘贴近工件）观测可能失效——文献
名为 state aliasing【证据，[paper_011](https://arxiv.org/abs/2603.01465)/[paper_029](https://arxiv.org/abs/2512.24638)】。
**尖锐推论**：现有 key_weight=3.0 落在"源帧在事件窗"，而事件窗恰是状态歧义重灾
区——×3 可能在强调不可学习的噪声（待测，假设 4）。标注必须对**模型实际输入
的表示**（缩放后）判定，不是原图【推理】。

### 4.3 验证回路：real2sim 捷径（OPT-002）

静态场景 + 稳态假设 ⇒ 成功 ⟺ 路径几何一致 ∧ 吸盘驻留一致。因此：
**oracle = 几何可行性 oracle：纯静态碰撞检测**（场景几何 + 机器人连杆 +
附着工件 + 事件窗驻留）；关节速度/加速度/力矩限幅作为后续 kinodynamic
gate，第一版不纳入【约束+推理】。
用途：(1) 给曲率重采样加可行性约束，把标签压得更稀；(2) 对绕路段做**捷径
修复**——直接生成更优路径（语义方案只能判断、不能生成）；(3) 与语义 agent
合成："语义指出哪段次优 + 几何生成捷径 + 物理验可行性"【推理】。
设计原则：重建有误差 ⇒ 障碍物**保守膨胀**（误拒好捷径安全，误收碰撞路径
致命）。oracle 自检须含正负对照：正对照 = 回放原始成功轨迹碰撞为零；
负对照 = 向已知障碍扰动轨迹必须报碰撞；记录 false-positive / false-negative 率
【推理】。

### 4.4 agent 与确定性工具的边界

| Agent 负责 | 确定性工具负责 |
|---|---|
| 识别任务阶段、解释停顿/绕路/纠错 | 时间对齐、数值检查、几何重采样 |
| 判断事件位置与观测可分性 | 图像变换、碰撞检测、插值 |
| 提出过滤/稀疏化/补采候选 | 按指定算法构建标签、导出格式 |
| 修订建议（基于验证结果） | 统计、验收、覆盖分析 |

【推理，与 DSPy"指标与管线分离"【证据，[paper_022](https://arxiv.org/abs/2310.03714)】及 AutoRT
"生成→自我批评→执行"【证据，[paper_019](https://arxiv.org/abs/2401.12963)】同构。第一版 agent 只做"诊断+标注+
建议"，不自动删数据【推理】。

### 4.5 现有系统的设计规律（归纳自 35 篇，供管线设计参照）

**责任边界的四条分界线**（本调研纳入的系统均遵守）：
1. **判断/执行分界**：LLM/VLM 只做语义判断；数值/几何/时序由确定性工具执行
   （DSPy 的"指标与管线分离"是其最明确的表述【证据，[paper_022](https://arxiv.org/abs/2310.03714)】）。
2. **生成/验证分界**：验证器永远独立于生成器——rollout 成功检查
   【[paper_024](https://arxiv.org/abs/2310.17596)/[paper_021](https://arxiv.org/abs/2509.20070)】、人类过滤/复核【[paper_020](https://arxiv.org/abs/2309.14320)/[paper_001](https://arxiv.org/abs/2403.12945)/[paper_030](https://arxiv.org/abs/2412.13877)】。
   没有系统让 LLM 自我验收。
3. **人机分界**：人守规则层（定义标准）与例外层（审边缘案例），不做全量执行
   （AutoRT 1 人监督 3–8 台【[paper_019](https://arxiv.org/abs/2401.12963)】）。
4. **软/硬约束分界**：软约束在 prompt（Robot Constitution），硬约束在工具/
   硬件（力阈值急停）【[paper_019](https://arxiv.org/abs/2401.12963)】。

**构成的五个常备件**：决策核心（单个 LLM/VLM）+ 工具集 + 批评者（生成-批评
成对出现）+ 显式状态工件（语言地图/taxonomy/编译程序）+ 外置指标函数。

**层次结构的通用四层模式**：规则层（人写声明式标准）→ 决策层（LLM 判断/
提议）→ 执行层（确定性工具）→ 验证层（执行反馈 + 人类例外审查）；
反馈从验证层向上流（rollout 结果→分类器、策略评估→修订采集协议）。

**八条通用原则**：①判断与执行分离；②生成与验证分离（验证器独立，优先
物理/执行/人类）；③质量定义外置为可测指标；④人类守规则层与例外层；
⑤约束分层（软在 prompt、硬在工具）；⑥状态外置为显式可溯源工件；
⑦下游验收是唯一终审（[paper_005](https://arxiv.org/abs/2606.10229) 教训）；⑧失败与拒绝本身是数据（保留并
标注原因，防覆盖偏置）。

**映射到本项目**：规则层=数据定义+QA 标准+事件判据+稳态假设（人写、版本化、
进 provenance）；决策层=VLM/LLM（旋钮 1/2/4 的判断+解释+候选，配批评者）；
执行层=曲率重采样+碰撞 oracle+时间对齐+格式导出；验证层=三臂下游对比+
oracle 自检+人审边缘案例。

## 5. 风险与未决

### 5.1 负面证据清单（设计必须规避的坑）

1. 离线指标与下游脱钩【[paper_005](https://arxiv.org/abs/2606.10229)/[paper_014](https://arxiv.org/abs/2606.15064)】→ 一切过滤/加权以下游成功率验收。
2. 开源小 VLM 语义进度预测接近随机【[paper_010](https://arxiv.org/abs/2509.17321)】→ 旋钮 1/2 的 VLM 选型要
   先做能力测试；旋钮 4 的可见性判断有 grounding 模型兜底，风险较低。
3. LLM-as-judge 有系统偏差（position/verbosity/self-enhancement）【[paper_008](https://arxiv.org/abs/2306.05685)】→
   打分设计要随机化位置、控制输出长度。
4. naive 成功过滤有覆盖偏置（43.5–66.4%）【[paper_024](https://arxiv.org/abs/2310.17596)】→ 过滤后必须查覆盖。
5. 速度无关性在接触任务不成立【[paper_026](https://arxiv.org/abs/2412.03252)】→ 任务扩展的边界检查。

### 5.2 证据缺口（文献没回答的问题）

- **GAP-03**："成功但次优"演示的过滤——无人研究。我们的核心问题，风险与
  原创性并存。
- **GAP-02**：语义过滤的下游定量收益——无任何数字。
- **GAP-08**：逐帧观测可分性标注——本轮文献未发现。
- **GAP-09**：train/val 划分协议——文献沉默，需自验。
- **GAP-10**：遥操数据多传感器同步——需自建工具。
- **GAP-11**：agent 运营 VLA 数据处理管线的系统——严格口径在已声明检索范围内未发现
  （定向检索确认）。组件级先例齐全：VLM/LLM 管线组件（OpenGVL/LLM Trainer/
  MUTEX/DROID/RoboMIND）、agentic 非机器人管线（AgentInstruct/DSPy/TextGrad）、
  agent 采集（AutoRT）、无 LLM 经典策展（SCIZOR/ATHENA/Demo-SCORE）。
  系统组合原创性成立，单一组件无新颖性。

### 5.3 专利性初判（非法律意见）

- 几何核（曲率密度 + 经典指数 1/3）是教科书结果，单独申请 novelty 薄弱
  【证据，现有方法包自述"经典结果"】。
- 潜在可辩护核心 = 系统组合："agent 自主决定标签构造旋钮 + 几何执行 +
  验证回路"。须避开 keyframe 训练检测器【[paper_011](https://arxiv.org/abs/2603.01465)】与进度预测策展
  【[paper_010](https://arxiv.org/abs/2509.17321)】的权利要求边角。
- 前置条件：专利库 prior art 检索；组合权利要求需要**可测的协同效应证据**。
  顺序：证据先行、专利后评。风险：ML 管线专利面临抽象客体审查；本包 2026-08
  起已随协作分发（自披露计时已开始）。

## 7. 术语速查

- **曲率重采样**：按 |q''|^(1/3) 密度稀疏取点重建动作标签（现有方法）。
- **事件窗**：吸盘触发 + 真空建立的帧区间，按时间保护、loss ×3。
- **次优解**：能完成但非最优的遥操演示（绕路、犹豫）；几何不可见。
- **state aliasing**：视觉相同但应有不同动作的帧（观测不可分）。
- **脱钩**：指标好 ≠ 下游策略好；本文指过滤指标的检出能力与策略收益无关。
- **执行反馈**：用真实/模拟执行结果做判据（rollout 成功、碰撞检验）。
- **GVL/VOC**：VLM 预测逐帧任务进度 / 进度与帧序的秩相关（质量度量）。
- **稳态假设**：静态场景下，路径+吸盘驻留一致 ⇒ 成功，速度无关。
- **real2sim oracle**：静态碰撞检测（重建场景 + 机器人 + 附着工件 + 事件窗）。
