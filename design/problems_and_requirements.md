# 数据处理系统：问题、方案与需求

> 当前实际遇到的问题、现有解法与局限性、预处理系统的必需功能与接口组成，
> 以及问题对应的社区/论文讨论。供设计评审与协作讨论。
> 与框架的关系：本文件对应 `docs/reports/top_level_view.md` 的管线面/旋钮面/
> 决策面；标准流程部分对应 `docs/design/design_framework.md` L0 十模块。

## 0 收束后的总路线（与协作方确认，2026-09-08）

**北星：vision / language / action 三模态对齐**——把 action 序列视作一种模态，
其增强方式必须以"与 vision、文本 prompt 对齐"为目标。

**立场转变**：

- 纯几何重采样（曲率密度 `|q''|^(1/3)`）以"表示误差"为目标，可能**破坏模态
  对齐**：跳帧/非均匀重排 → action 序列与观测帧的对应关系错位（`delta_timestamps`
  语义被打破）；必要停顿被压低密度 → 停顿若是对齐证据（吸盘驻留、对位）则
  不是可忽略冗余。
- 因此 **⑥ 标签构建的目标改为"模态对齐"**：曲率重采样降格为候选策略之一；
  事件窗时间保护保留（驻留属于对齐范畴，见 issues.md ISSUE-001 对照）。

**新增研究对象**：

1. **action 序列模式聚类**：pick 指令 ↔ 一类同构 action 序列簇；增强应忠实
   于簇模式而非单条最优轨迹；
2. **对齐后的 action 增强**：仿真里良好但不可直接迁移的 action label，经
   对齐（状态/动作空间或 embedding 层面）后可泛化应用于微调增强
   （sim→real action transfer；OPT-002 的复活与扩展）；
3. **动作模态 ↔ vision/text 的对齐度量**：文献侧无现成覆盖（新调研缺口，
   见 logs/decision_log.md）。

**保留不动**：状态机前四模块与验收；三诊断（`H(ℓ|v)`、视觉条件动作歧义度、
几何代理掩码——它们本是跨模态互信息代理，现在是"对齐度量"家族）；
消费契约（若最终保留非等时标签，契约必须在）。

**与 RL 的边界（不变）**：对齐增强管预训练/微调的数据面；RL 管行为后训练
面；两者互补不竞争（增强 → 预训练对齐 → RL 后训练）。

**第一可测步骤**（比之前更聚焦）：`H(ℓ|v)`（可视的跨模态冗余）+ 
prompt↔action 互信息/对齐度（动作模态对齐的初始度量，待设计）。

## 1 问题介绍

### 1.1 动作标签质量（停顿、次优、抖动、多样性不足）

四个现象成因不同，不能混为一谈：

| 现象 | 成因 | 迹象 | RL 可缓解性 |
|---|---|---|---|
| 停顿 | 操作者犹豫；时间轴均匀采样把监督密度分给静止帧 | 19% 帧只占 0.23% 关节行程 | 无（标签构造问题，已由重采样解决） |
| 遥操抖动 | 采集通道噪声（人→机械臂映射） | 轨迹平滑极限 1.97 mm（噪声地板） | 部分（行为平滑可由奖励项缓解；表示误差在数据侧） |
| **次优解** | 操作者选了一条能完成但非最优的路径（绕路、犹豫后折返） | **几何不可见**：绕路=拐弯=高曲率，反而消耗更多点 | **行为层部分可**（RL 可发现更优策略，但成功率奖励不编码"最优"→ 需时间型奖励）；**标签层不可** |
| 多样性不足 | 覆盖不够（任务/场景/视角/事件类型） | 覆盖矩阵稀疏；OOD 能力弱 | **强**（RL rollout 本身就是数据多样性来源，即 flywheel 机制） |

### 1.2 采集端 gap

- 操作员没有戴 VR 眼镜直接作业：人用肉眼/全视场/原始分辨率/力觉做决策，
  模型只有固定相机 + 处理后输入——对应"遥操 ↔ 模型输入的信息通道差"。
- 相机框取层级的配置问题（例如镜头区域没对准关键动作区），采集时不易察觉。
- 该 gap 的特征：**动作所依赖的信息可能根本不在观测里**（ISSUE-002），
  与"观测相同但动作不同"的状态歧义（ISSUE-003）成因不同但需同一套测量区分。
- **RL 可缓解性：信息缺失本身不可**；唯一正贡献——RL 可**放弃操作员策略**，
  自主探索出一条只用相机信息就可达的策略（BC 只能模仿用眼的操作员）。
  能观测到的部分（行为层面）RL 可修复；信息通道本身只能上游改采集。

### 1.3 prompt 在特定姿态区分度不足（终态歧义，已实测）

- 多任务共用同一 home 位姿（跨集关节差 0.0036 rad），终态与另一任务起始态
  在观测上重合（ISSUE-003）：放件末尾（空载·停）与取件起始（空载·走）画面一致。
- 条件分布上 prompt 可分（3.2% vs 100%），但该帧 prompt 行为信噪比仅 2.8×
  （中段 75.1×）；视觉先验推不动 440 mm 的基线。
- **歧义 ≠ 信息缺失**：信息在（编码探针 100%），是模型在该状态不使用 prompt。
- **RL 可缓解性：不行。** 歧义态下 RL 的最优策略收敛到边际平均（混合或沿
  多数行为），不会"发现 prompt 该被用"；且部署是连续流程，该"错误"动作
  在下一任务上下文里可能反而正确——这是任务边界建模 + 接口契约问题，
  修复在数据/接口/训练压力侧（§3.2）。RL 只有在 reward 显式区分两行为时
  才可能有梯度，而那等价于我们的人工介入。

### 1.4 关键帧加权有时起反作用

- 关键帧（事件窗）按"末端执行器状态切换"定位，而该时刻观测可能不可分或
  被遮挡（吸盘贴近工件、相机被遮挡）——这时 ×3 加权在强调不可学习的噪声。
- 判断关键帧需要"任务关键时刻"语义 + "该帧观测可用"可分性（二者缺一不可）。
- **RL 可缓解性：无关。** 这是训练数据构造（判据+权重落点）问题，RL 不消费
  标签构造细节，即使 RL 后训练也无法修复被错误加权的预训练阶段。

## 2 现有解法与局限性

| 问题 | 现有解法 | 局限性 |
|---|---|---|
| 停顿 | 曲率重采样（`|q''|^(1/3)` 进度坐标） | 已解决：停顿密度 0.070× |
| 抖动 | 重采样取点 + PCHIP 平滑 | 受 1.97 mm 噪声地板限制；重建误差 4 mm 对模型 7.3 mm 不再是瓶颈 |
| **次优解** | 无 | 几何与语义正交，几何不可见（GAP-03，文献空白） |
| 多样性不足 | 人机回环补采（AgiBot 模式） | 需覆盖分析与补采建议，目前无工具 |
| 部署适配 | 专属运控（dt_min 调度 + PCHIP + smoothstep + jerk 限幅） | 标签不等时是契约而非缺陷；换模型/换任务需重标定，速查表缺失 |
| 采集 gap | 无 | 线性探针可作下界诊断，但**编码 ≠ 使用**（能区分不代表模型会用） |
| prompt 区分度 | 无（新问题） | 训练侧候选均需验证（下述 §3/§4） |
| 关键帧加权 | key_weight=3.0 按事件窗 | 事件帧观测可能不可分；×3 可能放大噪声（待测推论，假设待测） |

**核心教训（调研结论）**：离线指标与下游收益会脱钩，一切改动以
下游策略成功率验收；"线性探针/编码性"只作下界诊断（必要条件），
"模型会使用"必须由行为证据（信噪比/方向对齐/停止率）证明。

**RL 边界**：上述问题中只有"行为层次优"与"多样性"是 RL  rollout 的直接
受益面；信息、语义判据、标签构造三类 RL 触碰不到——与其竞争的判定标准
见 §3.5.

## 3 必需功能与接口组成

设计原则：**标准流程做成纯程序状态机（确定性、可复现、可审计）；
只有语义判断才允许 LLM 参与。** 两者按"判断与执行分离"接入。

### 3.1 纯程序状态机（标准预处理流程）

= 十模块管线（`docs/design/design_framework.md` L0）。接口组成：

- 输入：数据集字典（schema：字段语义/单位/坐标系/版本，`data_schema.yaml`）。
- 状态转移：定义 → 对齐 → 标注 → 清洗 → 观测 → 标签 → 划分 → 增强 → 导出 → 验收。
- 每步为纯函数（输入+配置→输出），配置与判据写入 provenance；
  可选增强在受约束条件下执行（保语义/保驻留/需验证与覆盖检查）。
- 输出：样本清单、标签列（含 `action_loss_weight`）、验收报告、补采建议。

### 3.2 必须由 LLM/多模态模型承担的部分（决策面）

| 功能 | 具体内容 | 输出形态 | 依据/先例 |
|---|---|---|---|
| prompt 重写与多样性 | 保持任务定义不变地改写（不加入事后信息；不把区分性挂在单个 token 上） | 改写后的 prompt 集 + 与任务定义的映射 | LLM Trainer/MUTEX（先例） |
| 关键帧可见性检查 | 多模态判断关键帧时刻的观测是否看得见/看得清（模型分辨率下） | 逐关键帧可见性标注 | 旋钮 4；VLM 可见性判断 |
| 关键帧/事件语义定义 | 任务相关关键时刻的判定与修订（事件泛化：EE 切换只是特例） | 事件区间标注 + 理由 | 旋钮 1 |
| 次优段识别 | 判定哪些段是绕路/犹豫（非失败、非停顿） | 次优段标注 + 解释 | 旋钮 2（GAP-03） |
| 采集建议 | 缺口定位（任务/场景/视角 × 哪类样本缺失）+ 原因 + 建议量级 | 补采建议报告 | RoboMIND 形态 |
| 运控建议与速查表 | 因标签不等时（重采样参数），向运控侧给出 dt 调度参数表与换算规则 | 速查表（v_nominal/dt_min 标定值、事件窗时间分配、PCHIP 参数） | 消费契约（现有包 §6） |

### 3.3 检测/诊断工具（程序化，非 LLM，提供下界判据）

| 工具 | 量什么 | 定位 |
|---|---|---|
| prompt-id 探针（冻结视觉特征分类器）→ `H(ℓ|v)` | 逐帧"语言必要度" | 训练前门控；数据卡片 |
| 视觉条件动作歧义度 | 视觉相似帧动作发散的帧 | 可分性风险候选（歧义≠不可分，需 conditioning 后升级） |
| 几何代理歧义掩码（如末端在 home 附近） | 初始实施阶段的代理 | 先在门控/测试里用，后由探针版本替换 |

### 3.4 接口组成总览

```
上游采集侧 ◀── 采集建议（缺口报告）
                │
数据字典(schema) → 纯程序状态机（十模块） → 标签列/权重列/标注列 + provenance
                │                              │
                ├── 语义判断接口（agent）─────┤
                │    prompt 改写 / 可见性检查 / 事件与次优定义 / 解释
                │                              ▼
                └── 检测工具接口（探针/歧义度） → 训练前门控 → 数据卡片

下游运控侧 ◀── 消费契约速查表（dt 调度 / 插值参数）
```

### 3.5 收敛边界：RL 可缓解性 + 最小化实现纲领

**RL 边界汇总结论**（详见 §1 各节）：

| 问题 | RL 可缓解 | 缓解手段归属 |
|---|---|---|
| 停顿 / 关键帧加权反作用 | 无（标签构造） | 数据侧 |
| 遥操抖动 | 部分（奖励可平滑行为；表示噪声在数据侧） | 数据侧为主 |
| 次优解 | 行为层部分可；标签层不可 | 数据侧 + 训练侧 |
| 采集 gap（信息缺失） | 不可（信息缺失）；RL 可改探索相机可达策略 | 采集侧 |
| prompt 歧义 | **不行**（收敛到边际平均；需接口/训练压力） | 数据/接口/训练侧 |
| 多样性不足 | 强（rollout 即数据来源） | RL 侧与数据侧共担 |

**最小化收敛纲领**（用户确认方向，2026-09-08；与 AGENTS.md"只实现最小必须机制"一致）：

```
第 0 步（纯程序，无 LLM 无 agent）：三个测量跑完
   几何代理歧义掩码 / H(ℓ|v) 探针 / 浪费点占比（首轮人工标注 20–50 集）
   → 裁决：GAP-11 是否真需求（测量值≈0 则转向 RL 路线）
第 1 步（LLM 组件，非 agent）：判据注入 + 可分性标注 + 人工抽查
   → 若语义层影响非零且 RL 触不到，进入第 2 步；否则停在状态机
第 2 步（唯一真循环）：双指标搜索（参数脚本化，分析由人读矩阵）
   → 若价值回体后仍需自动化，才考虑 agent 编排
第 3 步（可能永不建）：real2sim oracle、完整 agent 编排（三层次/批评者/DSPy）
```

**保留 = 状态机（现有包 90% 已实现，只包接口）+ 三个纯程序测量 + 最简 LLM
组件（判据注入+标注+人审）；后置 = 搜索循环、real2sim、自动补采建议、
速查表排版；不建 = agent 框架选型、多 agent、批评者、DSPy 编译。

**每一步都有退出条件**——最小实现路径本身就是最便宜的证伪实验：
测量值≈0 → 转向 RL；第 1 步无增益 → 停在状态机；第 2 步手工已够 → 不建 agent。

## 4 社区/论文讨论：结论分级与证据

> 分级说明（每条结论标注强度来源）：
> **[社区一致]** = 多篇或经典工作支撑；**[单篇受控]** = 单篇论文、受控实验或
> 有确证强度的测量；**[本项目实测]** = 协作侧数据上的测量（可复现）；
> **[引用未核验]** = 协作报告引用的论文，本仓库只核对了 arXiv ID，内容未逐字核验。
> 开放问题 = 尚无可靠结论或存在争论的点。

### 4.1 动作标签质量与重采样

**已确立：**

| 结论 | 强度 | 证据 |
|---|---|---|
| action chunking + temporal ensembling 有效（k=1 成功率 1% → k=100 44%；TE +3.3%） | 单篇受控 | https://arxiv.org/abs/2304.13705 |
| 语义关键帧优于固定步长采样（均值 92% vs 57%；固定步长存在 horizon-resolution 权衡） | 单篇受控 | https://arxiv.org/abs/2603.01465 |
| 曲率密度取 `|q''|^(1/3)` 在两种插值方式下均优于 1/2、1/4（线性 13.60 vs 18.29/15.19；PCHIP 10.41 vs 11.81/10.91）；等弧长是**最差**规则（N=40 时 31.8 vs 曲率 11.8） | 本项目实测（社区无同构文献，GAP-06） | 现有包 `RESAMPLING_REPORT.md` 与 https://arxiv.org/abs/1907.03146（综述定位） |
| 速度类增强在接触/力控任务中不安全（真实反应 88% vs 时间缩放复制 31%） | 单篇受控（力控擦拭/搬运设定；本项目吸盘无接触段不违反） | https://arxiv.org/abs/2412.03252 |
| 增强轨迹需验证（真实执行+成功过滤），但 naive 成功过滤有覆盖偏置（43.5–66.4%） | 单篇受控 | https://arxiv.org/abs/2310.17596 |
| 离线 curation 指标的检出 AUROC 与下游增益**脱钩**（ρ=−0.14；AUROC 最高者下游最差） | 两篇独立受控（同为仿真单一缺陷 80% 污染，现实污染 20–40% 未测） | https://arxiv.org/abs/2606.10229 与 https://arxiv.org/abs/2606.15064 |
| 在线 rollout 策展是唯一带下游定量验证的形态（+15–40% 绝对成功率） | 单篇受控+公开实现 | https://arxiv.org/abs/2503.03707 |

**仍开放：**

- **"成功但次优"演示的识别与过滤**（GAP-03）：社区零文献——"次优"与"缺陷/失败"的界限没有可靠定义，是最开放的争议点。
- 离线指标哪些可靠没有一般答案：ensemble/trajectory alignment 在单设定下接近 oracle（91.1/90.0 vs 93.3），但为何有效不可由检出 AUROC 预测——机制不明确。
- 曲率重采样的方法学新颖性未验证（GAP-06）：社区无同构工作，不等于不存在。
- 停顿自动去权（19% 帧只占 0.23% 行程）是本项目实测，社区无对应讨论。
- 部署侧消费契约（不等时标签 → dt 调度）无社区论文，只有工程事实（openpi 生态 + 本项目 `chunk_playback.py`）。

### 4.2 采集端 gap 与观测信息

**已确立：**

| 结论 | 强度 | 证据 |
|---|---|---|
| 大规模数据集用"协议+人工/半自动分层质检"是常态（DROID 成功标记/AgiBot 人工核对/RoboMIND 8 条 QA 三步检查） | 社区一致 | https://arxiv.org/abs/2403.12945；https://arxiv.org/abs/2503.06669；https://arxiv.org/abs/2412.13877 |
| 人机回环有效（verified 528 条 vs unverified 482 条微调 +0.18 completion） | 单项目数据 | https://arxiv.org/abs/2503.06669 |
| 语言冗余有信息论判据：`H(ℓ|v) ≤ ε` 时纯视觉策略是最优（LIBERO 实测 1.6×10⁻⁹；pick-place 7.2×10⁻²） | 单篇受控（理论+两个域实测） | https://arxiv.org/abs/2512.11218 |
| 状态歧义可分类（五类）且模型侧工作记忆缓解有效（PAM 0.91 vs LongDP 0.61 / MTIL 0.45；口径注意：PAM 多任务训练 vs 基线单任务） | 单篇受控 | https://arxiv.org/abs/2512.24638 |
| **编码 ≠ 使用**：线性探针可解码不代表行为会使用（amnesic counterfactual 标准判据） | 社区一致（经典） | https://arxiv.org/abs/2006.00995 |
| VLM 时间进度预测能力差距大（开源约为闭源 60–70%；小模型接近随机） | 单篇受控 | https://arxiv.org/abs/2509.17321 |

**仍开放：**

- "操作员信息通道 vs 模型观测通道"的**测量标准**不存在（GAP-10、ISSUE-002）：探针是下界，不是标准；区分"缺少信息"与"存在但未使用"的项目测法还没有被社区定义。
- `H(ℓ|v)` 在本项目数据集上的实际值**未测**（协作报告明确标注）。
- 自动化"关键帧可见性"判断（旋钮 4 的可分性标注）在数据侧无先例（GAP-08）。

### 4.3 prompt 区分度与语言粒度

**已确立：**

| 结论 | 强度 | 证据 |
|---|---|---|
| 语言敏感度取决于任务/状态的歧义程度而非架构（`libero_goal` 错 prompt 94%→10%，`libero_object` 60–100%；激活注入 99.8% 对齐） | 单篇受控 | https://arxiv.org/abs/2603.19233 |
| 语言重要性是逐步的（非英语指令 30–50% 掉率；导航/抓取贡献 53%/18% 失败；梯度比指标 `r_t`） | 单篇受控（具体模型与干预提升幅度未核实） | https://arxiv.org/abs/2606.11906 |
| 强视觉先验可压倒稀疏语言信号（模态坍缩机制） | 单篇定性/机制 | https://arxiv.org/abs/2601.04052 |
| 语义上"取 vs 放"的词面距离与行为影响力无关（P2 词面更远、影响力反而更小 56.0 mm vs P1 64.7 mm） | 本项目实测（5 episode×6 采样，样本少） | 协作报告 `WHY_IT_DOES_NOT_STOP.md` |

**仍开放：**

- **推理侧放大语言**：本项目三种机制（重复 prompt / 激活外推 / embedding 缩放）全部独立失败，且缩放破坏分布（首帧跳变 0.5 rad）——社区无系统研究（Grant/Dong 均是训练/评测侧），开放式问题。
- prompt 词面设计与行为杠杆的关系：本项目的一个反例（P1/P3 Jaccard 0.560，辨别由动词承载），无社区结论。
- 多任务混合下 prompt-行为对应设计——开放。

### 4.4 关键帧/事件帧观测不足

**已确立：**

| 结论 | 强度 | 证据 |
|---|---|---|
| 状态歧义五类分类（双向重叠/固定时长静止/顺序子任务依赖/重复循环/动态交互响应） | 单篇受控（描述性分类） | https://arxiv.org/abs/2512.24638 |
| 结构化视觉遮蔽收益来自结构而非遮蔽本身（M3 64.0% vs 无遮蔽 23.7%、随机 token dropout 31.8%；但细粒度关系推理接近零） | 单篇受控 | https://arxiv.org/html/2608.22419 |
| 子任务辅助 CE 的前提：当任务真相透明时该损失无解（SALT） | 引用未核验（本仓库仅核验 ID；协作报告描述了机制） | https://arxiv.org/abs/2608.10484 |

**仍开放：**

- 逐帧可分性标注（数据侧）无先例（GAP-08）——实现路线（几何代理→探针→歧义度分级）尚无社区评价。
- 关键帧加权是否"踩雷"（事件窗源帧的视觉可分性分布）——待测（ISSUE-003 假设 2 / 旋钮 4）。
- 关键帧可见性检查的定量收益——开放。

## 5 未决决策点

1. **终态设计**（ISSUE-003）：place 结束位置 = 释放点 vs home；
   回位归任务还是归调度器——由采集/部署侧拍板，预处理执行裁剪或分家。
2. **阈值标定**：歧义帧份额门控阈值（当前输出标记不干预，随训练记录标定）。
3. **探针-使用gap**：所有"信息在"类结论（H(ℓ|v)=0、编码探针 100%）都只是
   必要条件；"模型是否会使用"必须由行为指标（行为 SNR/方向对齐/停止率）
   下结论——这是本项目贯穿性的纪律。
4. **RL 路线 vs 数据路线裁决**：第 0 步三个测量（几何代理歧义掩码、
   H(ℓ|v) 探针、浪费点占比）的结果决定 GAP-11 是真需求还是应转向
   RL rollout（§3.5 退出条件）；测量值≈0 时降级为候选并记录。
