> 当前实际遇到的问题、现有解法与局限性、预处理系统的必需功能与接口组成，
> 以及问题对应的社区/论文讨论。供设计评审与协作讨论。
> 与框架的关系：本文件对应 `docs/reports/top_level_view.md` 的管线面/旋钮面/
> 决策面；标准流程部分对应 `docs/design/design_framework.md` L0 十模块。

## 1 问题介绍

### 1.1 动作标签质量（停顿、次优、抖动、多样性不足）

四个现象成因不同，不能混为一谈：

| 现象 | 成因 | 迹象 |
|---|---|---|
| 停顿 | 操作者犹豫；时间轴均匀采样把监督密度分给静止帧 | 19% 帧只占 0.23% 关节行程 |
| 遥操抖动 | 采集通道噪声（人→机械臂映射） | 轨迹平滑极限 1.97 mm（噪声地板） |
| **次优解** | 操作者选了一条能完成但非最优的路径（绕路、犹豫后折返） | **几何不可见**：绕路=拐弯=高曲率，反而消耗更多点 |
| 多样性不足 | 覆盖不够（任务/场景/视角/事件类型） | 覆盖矩阵稀疏；OOD 能力弱 |

### 1.2 采集端 gap

- 操作员没有戴 VR 眼镜直接作业：人用肉眼/全视场/原始分辨率/力觉做决策，
  模型只有固定相机 + 处理后输入——对应"遥操 ↔ 模型输入的信息通道差"。
- 相机框取层级的配置问题（例如镜头区域没对准关键动作区），采集时不易察觉。
- 该 gap 的特征：**动作所依赖的信息可能根本不在观测里**（ISSUE-002），
  与"观测相同但动作不同"的状态歧义（ISSUE-003）成因不同但需同一套测量区分。

### 1.3 prompt 在特定姿态区分度不足（终态歧义，已实测）

- 多任务共用同一 home 位姿（跨集关节差 0.0036 rad），终态与另一任务起始态
  在观测上重合（ISSUE-003）：放件末尾（空载·停）与取件起始（空载·走）画面一致。
- 条件分布上 prompt 可分（3.2% vs 100%），但该帧 prompt 行为信噪比仅 2.8×
  （中段 75.1×）；视觉先验推不动 440 mm 的基线。
- **歧义 ≠ 信息缺失**：信息在（编码探针 100%），是模型在该状态不使用 prompt。

### 1.4 关键帧加权有时起反作用

- 关键帧（事件窗）按"末端执行器状态切换"定位，而该时刻观测可能不可分或
  被遮挡（吸盘贴近工件、相机被遮挡）——这时 ×3 加权在强调不可学习的噪声。
- 判断关键帧需要"任务关键时刻"语义 + "该帧观测可用"可分性（二者缺一不可）。

## 2 现有解法与局限性

| 问题 | 现有解法 | 局限性 |
|---|---|---|
| 停顿 | 曲率重采样（`|q''|^(1/3)` 进度坐标） | 已解决：停顿密度 0.070× |
| 抖动 | 重采样取点 + PCHIP 平滑 | 受 1.97 mm 噪声地板限制；重建误差 4 mm 对模型 7.3 mm 不再是瓶颈 |
| **次优解** | 无 | 几何与语义正交，几何不可见（GAP-03，文献空白） |
| 多样性不足 | 人机回环补采（AgiBot 模式） | 需覆盖分析与补采建议，目前无工具 |
| 部署适配 | 专属运控（dt_min 调度 + PCHIP + smoothstep + jerk 限幅） | 标签不等时是契约而非缺陷；换模型/换任务需重标定，速查表缺失 |
| 采集 gap | 无 | 线性探针可作下界诊断，但**编码 ≠ 使用**（能区分不代表模型会用） |
| prompt 区分度 | 无（新问题） | 训练侧候选均需验证（下述 §3/§4） |
| 关键帧加权 | key_weight=3.0 按事件窗 | 事件帧观测可能不可分；×3 可能放大噪声（待测推论，假设待测） |

**核心教训（调研结论）**：离线指标与下游收益会脱钩，一切改动以
下游策略成功率验收；"线性探针/编码性"只作下界诊断（必要条件），
"模型会使用"必须由行为证据（信噪比/方向对齐/停止率）证明。

## 3 必需功能与接口组成

设计原则：**标准流程做成纯程序状态机（确定性、可复现、可审计）；
只有语义判断才允许 LLM 参与。** 两者按"判断与执行分离"接入。

### 3.1 纯程序状态机（标准预处理流程）

= 十模块管线（`docs/design/design_framework.md` L0）。接口组成：

- 输入：数据集字典（schema：字段语义/单位/坐标系/版本，`data_schema.yaml`）。
- 状态转移：定义 → 对齐 → 标注 → 清洗 → 观测 → 标签 → 划分 → 增强 → 导出 → 验收。
- 每步为纯函数（输入+配置→输出），配置与判据写入 provenance；
  可选增强在受约束条件下执行（保语义/保驻留/需验证与覆盖检查）。
- 输出：样本清单、标签列（含 `action_loss_weight`）、验收报告、补采建议。

### 3.2 必须由 LLM/多模态模型承担的部分（决策面）

| 功能 | 具体内容 | 输出形态 | 依据/先例 |
|---|---|---|---|
| prompt 重写与多样性 | 保持任务定义不变地改写（不加入事后信息；不把区分性挂在单个 token 上） | 改写后的 prompt 集 + 与任务定义的映射 | LLM Trainer/MUTEX（先例） |
| 关键帧可见性检查 | 多模态判断关键帧时刻的观测是否看得见/看得清（模型分辨率下） | 逐关键帧可见性标注 | 旋钮 4；VLM 可见性判断 |
| 关键帧/事件语义定义 | 任务相关关键时刻的判定与修订（事件泛化：EE 切换只是特例） | 事件区间标注 + 理由 | 旋钮 1 |
| 次优段识别 | 判定哪些段是绕路/犹豫（非失败、非停顿） | 次优段标注 + 解释 | 旋钮 2（GAP-03） |
| 采集建议 | 缺口定位（任务/场景/视角 × 哪类样本缺失）+ 原因 + 建议量级 | 补采建议报告 | RoboMIND 形态 |
| 运控建议与速查表 | 因标签不等时（重采样参数），向运控侧给出 dt 调度参数表与换算规则 | 速查表（v_nominal/dt_min 标定值、事件窗时间分配、PCHIP 参数） | 消费契约（现有包 §6） |

### 3.3 检测/诊断工具（程序化，非 LLM，提供下界判据）

| 工具 | 量什么 | 定位 |
|---|---|---|
| prompt-id 探针（冻结视觉特征分类器）→ `H(ℓ|v)` | 逐帧"语言必要度" | 训练前门控；数据卡片 |
| 视觉条件动作歧义度 | 视觉相似帧动作发散的帧 | 可分性风险候选（歧义≠不可分，需 conditioning 后升级） |
| 几何代理歧义掩码（如末端在 home 附近） | 初始实施阶段的代理 | 先在门控/测试里用，后由探针版本替换 |

### 3.4 接口组成总览

```
上游采集侧 ◀── 采集建议（缺口报告）
                │
数据字典(schema) → 纯程序状态机（十模块） → 标签列/权重列/标注列 + provenance
                │                              │
                ├── 语义判断接口（agent）─────┤
                │    prompt 改写 / 可见性检查 / 事件与次优定义 / 解释
                │                              ▼
                └── 检测工具接口（探针/歧义度） → 训练前门控 → 数据卡片

下游运控侧 ◀── 消费契约速查表（dt 调度 / 插值参数）
```

## 5 未决决策点

1. **终态设计**（ISSUE-003）：place 结束位置 = 释放点 vs home；
   回位归任务还是归调度器——由采集/部署侧拍板，预处理执行裁剪或分家。
2. **阈值标定**：歧义帧份额门控阈值（当前输出标记不干预，随训练记录标定）。
3. **探针-使用gap**：所有"信息在"类结论（H(ℓ|v)=0、编码探针 100%）都只是
   必要条件；"模型是否会使用"必须由行为指标（行为 SNR/方向对齐/停止率）
   下结论——这是本项目贯穿性的纪律。
